#### Style Stack

I enjoy visual design, but for most projects the UI is not the biggest area of exploration.

In order to skip that step, while also maintaining quality in the work, I have created a set of styles with design instructions that help me set up a simple visual language fast.

This is the style stack.

---
### Pen and Paper


Minimal lines and plain surfaces. A visual language that feels made by hand. For limited interactivity or fluid interfaces. 

Drawings, sketches, strokes, annotations, and textures. The interface should feel exploratory and lightweight.

{{< accordion title="Instructions" >}}
Use a minimal, hand-drawn visual language. Keep the interface close to a page in a notebook, a working sketch, or a collection of annotations.

LAYOUT
Use open layouts with plenty of whitespace.
Avoid rigid grids unless the content requires them.
Keep the number of visible sections low.
Use simple horizontal and vertical alignment.
Allow slight irregularities in spacing and positioning.
Prefer content placed directly on the page over content inside cards or containers.
Use thin lines to separate sections instead of filled surfaces.
Keep navigation minimal and unobtrusive.

COLOUR
Use plain, light backgrounds such as off-white, paper white, or very light grey.
Use black, charcoal, or graphite for primary text and strokes.
Use muted colours sparingly for highlights, annotations, or emphasis.
Avoid gradients, saturated colour palettes, and decorative colour blocks.
Keep the overall palette limited to three or four colours.

TYPOGRAPHY
Use simple, highly readable typography.
Prefer neutral sans-serif fonts for interface text.
Use handwritten or sketch-like typography only for occasional annotations and labels.
Keep headings relatively small and understated.
Use changes in weight and spacing to establish hierarchy.
Avoid excessive typographic variation.

LINES AND SURFACES
Use thin strokes, generally 1px or 1.5px.
Allow lines to have slight variations in weight or shape.
Use hand-drawn outlines for selected elements.
Keep backgrounds flat and surfaces unadorned.
Use subtle paper textures only when they do not interfere with readability.
Avoid drop shadows, gradients, glossy finishes, and elaborate borders.
Do not make every element look hand-drawn. Keep the treatment selective and consistent.

COMPONENTS
Buttons should look like simple labels or lightly outlined controls.
Inputs should use minimal borders, underline treatments, or simple rectangular outlines.
Use small hand-drawn arrows, marks, circles, and underlines for annotations.
Use simple checkboxes and radio controls.
Prefer text links over prominent button treatments.
Keep icons minimal and use hand-drawn icons only where appropriate.
Use plain dividers instead of cards wherever possible.
Avoid complex menus, floating toolbars, and excessive controls.

INTERACTION
Keep interactions limited.
Use simple, direct transitions.
Avoid elaborate animations, parallax, and animated decoration.
Use a clear visual change for selected, active, and completed states.
Make focus states visible through a change in stroke or underline.
Keep hover states subtle.
Do not rely on animation to communicate important information.

RESPONSIVE BEHAVIOUR
Preserve the open, page-like layout on smaller screens.
Stack sections vertically when necessary.
Allow drawings and annotations to scale without becoming illegible.
Keep controls comfortably sized for touch.
Remove decorative elements before compromising content space.

AVOID
Heavy card-based layouts.
Complex component styling.
Excessive colour.
Perfectly uniform decorative elements.
Unnecessary borders and dividers.
Large shadows and gradients.
Overly playful illustrations.
Decorative elements that compete with the content.
{{< /accordion >}}

### Modern Minimalism

Apple or Instagram. Visual design made for millions.

Clean, neutral, and intentionally characterless. Everything is there for a purpose. The interface should not ask for attention when the product itself can have it

A familiar visual language built around consistency, clarity, and restraint.

{{< accordion title="Instructions" >}}
Use a clean, neutral, highly consistent interface. Every element should have a clear visual role. Keep decoration to a minimum and use spacing, typography, and alignment to establish hierarchy.

LAYOUT
Use a consistent 8px spacing system.
Build layouts around clearly defined columns and alignment guides.
Keep page margins consistent.
Use generous spacing between major sections and tighter spacing within related groups.
Align text, controls, icons, and containers precisely.
Use a clear hierarchy of page title, section heading, content, and supporting information.
Prefer flat page layouts over deeply nested containers.
Use cards only when separate content groups need to be distinguished.
Keep navigation simple and consistent across screens.
Use a predictable layout for recurring page types.

COLOUR
Use white or near-white as the primary background.
Use black or dark grey for primary text.
Use medium grey for secondary text.
Use light grey for borders, separators, and subtle backgrounds.
Use one accent colour for primary actions, selection, and important interactive states.
Do not introduce additional colours without a functional reason.
Use semantic colours consistently for success, warning, and error states.
Avoid gradients, noisy textures, and decorative colour combinations.

TYPOGRAPHY
Use a neutral sans-serif typeface.
Use a restrained type scale with clear differences between headings, body text, labels, and metadata.
Use font weight to establish hierarchy rather than relying on excessive changes in size.
Keep body text comfortable to read.
Use consistent line heights and letter spacing.
Avoid unnecessary all-caps text.
Use tabular numerals for values, statistics, prices, and metrics.
Keep labels short and direct.

SPACING AND SHAPE
Use consistent padding across similar components.
Use moderate corner radii, generally between 6px and 12px.
Use thin, low-contrast borders where separation is necessary.
Avoid unnecessary shadows.
Use subtle background differences to distinguish grouped content.
Keep component heights and control dimensions consistent.
Do not mix multiple radius styles without a clear hierarchy.

COMPONENTS
Buttons should have simple shapes, clear labels, and predictable hierarchy.
Use one prominent primary action per section where possible.
Secondary actions should be visually quieter.
Inputs should use consistent heights, padding, and border treatments.
Use simple line icons with consistent stroke weight.
Use standard checkboxes, radio buttons, toggles, and dropdowns.
Keep tables clean with clear column alignment and subtle row separators.
Use simple tabs and navigation indicators.
Keep cards flat, with minimal borders and no unnecessary decoration.
Use consistent empty states, loading indicators, and feedback messages.
Use familiar patterns for menus, dialogs, tooltips, and notifications.

INTERACTION
Use subtle transitions, generally between 150ms and 250ms.
Use clear hover, focus, pressed, selected, disabled, and loading states.
Buttons should provide immediate interaction feedback.
Use consistent focus indicators.
Do not use animation unless it communicates a change in state.
Keep transitions simple and avoid exaggerated movement.
Use consistent validation and error treatments.
Make the active navigation item immediately recognisable.

RESPONSIVE BEHAVIOUR
Use fluid widths and responsive columns.
Collapse multi-column layouts into a single column when space becomes limited.
Keep content margins consistent across screen sizes.
Prioritise the main content over secondary navigation and supporting elements.
Use mobile navigation patterns only when required.
Maintain consistent control sizes and spacing across devices.
Prevent horizontal scrolling unless the interface explicitly requires it.

AVOID
Decorative illustrations and unnecessary visual effects.
Excessive gradients and shadows.
Inconsistent component styling.
Unnecessary animation.
Too many accent colours.
Overly rounded components.
Excessive cards and nested containers.
Visual hierarchy created through decoration rather than layout and typography.
{{< /accordion >}}

### Early Computing

Lisa. Early windows. Old Reddit.

Some of the earliest recognisable interface conventions. Boxy, barebones, and structured. Everything has a place, and the interface makes that structure visible.

Useful when organisation matters. Panels, lists, borders, menus, and clear groupings make complex information easier to understand and interact with.

{{< accordion title="Instructions" >}}
Use a box-based interface inspired by early desktop operating systems, window managers, and old web interfaces. Make the structure visible through panels, borders, title bars, menus, and clearly separated controls.

LAYOUT
Use a strict grid.
Organise content into rectangular sections and panels.
Use visible boundaries between different interface areas.
Prefer fixed or clearly defined panel dimensions where appropriate.
Use compact spacing.
Keep related controls grouped together.
Use horizontal and vertical dividers to establish structure.
Use persistent navigation areas, sidebars, toolbars, and status bars where necessary.
Make the information hierarchy explicit.
Use multiple panes when users need to work across related information.
Keep the layout dense but orderly.
Align labels and values consistently.

WINDOWS AND PANELS
Use rectangular windows with visible title bars.
Give title bars a distinct background or border treatment.
Use square corners.
Separate window content from window controls using clear dividers.
Use simple minimize, maximize, and close controls when the interface calls for desktop-window conventions.
Use overlapping windows only when necessary.
Use inset or bordered content areas to distinguish editable regions.
Make active and inactive panels visually distinct.
Use consistent border weights across windows and panels.

COLOUR
Use a limited palette.
Prefer light grey, warm grey, off-white, and muted system colours for primary surfaces.
Use darker grey or black for text and outlines.
Use one or two strong colours for active states and important actions.
Use high-contrast colours for selected items and keyboard focus.
Use flat colour fills.
Avoid gradients, translucency, blur, and layered glass effects.
Keep colours functional and consistent.

TYPOGRAPHY
Use simple system sans-serif typography.
Use compact type sizes for menus, labels, and metadata.
Use slightly larger text for window titles and primary headings.
Use monospace typography for technical values, logs, file paths, and code.
Keep line heights compact but readable.
Use consistent text alignment.
Prefer clear labels over decorative headings.
Avoid oversized typography and expressive font combinations.

BORDERS AND SURFACES
Use visible 1px borders to define panels and controls.
Use stronger borders to separate major interface regions.
Use square corners throughout.
Use flat surfaces with little or no shadow.
Use inset and outset border treatments selectively for controls that need a desktop-computing feel.
Use simple horizontal separators in lists and menus.
Keep borders consistent in colour and weight.
Avoid modern floating-card treatments.

COMPONENTS
Use compact rectangular buttons.
Use traditional text fields with visible outlines.
Use dropdown menus with clear borders and simple selection indicators.
Use tab bars, menu bars, and toolbars with compact spacing.
Use rectangular checkboxes and radio controls.
Use clearly visible selected states in lists and tables.
Use dense tables with aligned columns and consistent row heights.
Use tree views and nested lists where hierarchical information is present.
Use simple progress bars and status indicators.
Use visible scrollbars where appropriate.
Use text-based icons or simple pixel-style icons.
Keep tooltips and contextual menus compact.
Use numbered pages or simple pagination for long lists.

INTERACTION
Use explicit interaction states.
Make selected, active, focused, disabled, and pressed elements visually distinct.
Use clear keyboard focus indicators.
Support keyboard navigation across menus, lists, and forms.
Keep interactions predictable and direct.
Use minimal transitions, preferably none.
Use simple hover highlights.
Make destructive actions visually distinct and provide clear confirmation where necessary.
Keep feedback messages within the relevant panel or status area.

RESPONSIVE BEHAVIOUR
Maintain the panel-based structure on smaller screens where possible.
Stack panels vertically when multiple columns no longer fit.
Convert sidebars into compact navigation when necessary.
Allow tables to scroll horizontally rather than compressing their contents beyond readability.
Keep title bars and controls usable on touch devices.
Preserve clear boundaries between sections.
Avoid shrinking the entire desktop interface to fit a smaller viewport.

AVOID
Rounded cards and pill-shaped controls.
Glassmorphism and translucent surfaces.
Gradients and elaborate shadows.
Oversized typography.
Floating elements without visible structure.
Excessive whitespace.
Modern decorative animations.
Unstructured content layouts.
Decorative icons that resemble neither interface controls nor information indicators.
